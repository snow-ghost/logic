# Расширенная проверка технического текста

Применять, если цена неточности высока или текст содержит сильные утверждения о качестве, безопасности, производительности, причинности, сравнительном преимуществе либо готовности решения. Цель проверки состоит в достоверности и воспроизводимости, а не в стилистическом единообразии.

## 1. Реестр утверждений

Для каждого существенного утверждения установить:

| Поле | Вопрос |
|---|---|
| Субъект | Какая система, часть или участник действует? |
| Действие | Что именно происходит? |
| Условия | При какой конфигурации, нагрузке или входных данных? |
| Результат | Какое наблюдаемое изменение получено? |
| Основание | Код, измерение, журнал, опыт эксплуатации, ссылка или вывод? |
| Статус | Реализовано, испытано, применяется, проектируется, планируется или предполагается? |

Ослабить формулировку или запросить данные, если основание отсутствует. Не придумывать подтверждение.

## 2. Статус реализации

Согласовать глаголы со статусом:

| Статус | Подходящие формулировки |
|---|---|
| Реализовано | «компонент выполняет», «добавлен обработчик» |
| Испытано | «проверено на», «испытание показало» |
| Применяется | «используется в», «обрабатывает в рабочей среде» |
| Спроектировано | «схема предусматривает», «определен протокол» |
| Планируется | «планируется добавить», «следующий этап включает» |
| Предположение | «предполагается проверить», «гипотеза состоит в» |

Не переносить результат отдельного опыта на всю систему. Не описывать план глаголом настоящего времени.

## 3. Сравнения и причинность

Для сравнительного утверждения указать:

- исходный вариант;
- новый вариант;
- одинаковые условия;
- измеряемую величину;
- размер и состав выборки;
- способ вычисления результата.

При отсутствии измерений заменить превосходство наблюдаемым архитектурным отличием.

Для причинного утверждения проверить наличие механизма и наблюдений. Формулировку «X снизил Y» использовать при контролируемом сравнении или достаточных эксплуатационных данных. В остальных случаях описывать совместное наблюдение либо ожидаемый эффект как гипотезу.

## 4. Полнота описания системы

Проверить, понятны ли:

- входные данные и их происхождение;
- преобразования и принимаемые решения;
- результат и его потребитель;
- место хранения состояния;
- условия повторного применения знаний;
- обработка ошибок и неполных данных;
- границы доверия и права доступа;
- действия, способные изменить рабочую среду;
- роль человека при проверке и публикации результата.

Добавлять отсутствующие сведения только из доступного источника. Иначе обозначать пробел вопросом автору.

## 5. Терминология

Составить краткое соответствие «понятие -> термин» и проверить весь текст. Различать близкие сущности: данные, сведения, знания, правило, сценарий, вывод модели, решение оператора. Синонимическая замена допустима только при сохранении предметного значения.

Раскрыть сокращения при первом употреблении. Сохранить общеупотребимые названия технологий в принятом написании.

## 6. Информационная плотность

Для каждого абзаца определить его функцию: постановка задачи, ограничение, устройство, пример, результат или вывод. Удалить предложения, которые лишь объявляют следующую мысль либо повторяют предыдущую без нового условия, механизма или следствия.

Разделить абзац, если он выполняет несколько функций. Объединить соседние абзацы, если второй только перефразирует первый.

## 7. Согласованность разделов

Проверить соответствие:

- название соответствует предмету и содержанию текста;
- каждый раздел развивает заявленную тему и выполняет понятную функцию;
- вводная часть объясняет назначение и границы материала без новых неподтвержденных фактов;
- вывод следует из приведенных данных;
- одинаковые числа, названия и статусы совпадают во всех разделах.

## 8. Итоговая проверка

1. Прочитать итог как специалист, который не видел исходных материалов.
2. Выписать утверждения, требующие доверия к автору без основания.
3. Сопоставить итог с источником и найти изменения фактов, условий, отрицаний и статуса.
4. Запустить диагностический сценарий с `--extended`.
5. Просмотреть каждое срабатывание вручную.
6. Вернуть готовый текст и отдельно назвать только те пробелы, которые нельзя устранить редактурой.
